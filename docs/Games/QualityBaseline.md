# 遊戲質感與 UX 基準

目前基準版本：**v1**

這份基準是新遊戲正式發布，以及既有遊戲完成品質改造時必須通過的驗收門檻。Puzzle Bobble 是第一個參考實作；後續遊戲應沿用原則，不必複製其霓虹視覺。

## 適用範圍與發布規則

- `planned`、`beta`、`published` 描述發布階段；品質驗證是另一個獨立維度。
- `beta` 可以公開試玩，但必須清楚標示為測試版；升為 `published` 前必須通過目前基準版本。
- 導入本基準前已發布的遊戲一律視為「尚未驗證」，不批次推定通過，也不因此撤下。
- 一般修正不代表完成品質改造。只有品質改造、基準升版，或 `beta` 準備升為 `published` 時，才強制執行完整驗證。
- 品質狀態目前只供內部驗收與維護，不顯示給玩家；玩家介面只顯示 `beta` 等發布階段。
- 驗證失敗不會自動改變發布階段。但若失敗證明核心遊玩循環無法完成、正式建置失敗或存在其他阻斷問題，遊戲已不符合正式發布定義，必須降級或撤下。

## 基準版本

- 基準使用單一遞增整數版本：`v1`、`v2`、`v3`。
- 可能改變任何遊戲通過結果的規範性變更必須升版。
- 錯字修正、未改變要求的措辭澄清，以及參考連結更新不升版。
- 每項要求都有固定 ID。單純改寫時保留 ID；要求真正改變時新增 ID，並標記舊 ID 已淘汰。

## v1 驗收項目

每項結果只能是 `pass`、`fail` 或 `n/a`。`n/a` 必須附理由；任一 `fail` 代表整體未達標，不設單一遊戲豁免。

### 核心體驗

- **PLAY-01**：能完成一次核心遊玩循環：開始、主要操作、結果回饋、代表性結束或目標狀態，以及重新開始。
- **PLAY-02**：有自然終點或關卡的遊戲至少完成第一個代表性目標；無限型遊戲必須實際觸發結束狀態並成功重開。
- **FEEDBACK-01**：命中、失誤、得分、危險與結束等關鍵結果有立即且清楚的回饋。
- **CONTROL-01**：隨時提供暫停與重新開始；使用音效時也必須提供音效開關。

### 輸入、版面與無障礙

- **INPUT-01**：核心玩法同時支援觸控、滑鼠，以及適合該玩法的鍵盤操作。
- **VIEW-01**：最新本機 Chrome 在至少 `1280 × 720` 的桌面視窗中可完整遊玩，無必要內容被裁切。
- **VIEW-02**：Chrome 裝置模式 `390 × 844` 中可完整遊玩，觸控有效、文字可讀，且無水平溢位。
- **A11Y-01**：主要按鈕與遊戲控制的可點擊範圍至少 `48 × 48` CSS px。
- **A11Y-02**：鍵盤焦點清楚可見；按鈕與互動控制有可辨識的無障礙名稱。
- **A11Y-03**：顏色不是唯一資訊來源；重要顏色狀態另有符號、形狀或文字。
- **READ-01**：關鍵數字、狀態與操作說明有足夠字級、對比與間距，可直接閱讀。
- **CANVAS-01**：使用 Canvas 時依裝置像素比繪製，並限制最大倍率以兼顧清晰度與效能。

### 素材與效果

- **ASSET-01**：第三方素材允許專案用途，並在相鄰目錄保留來源網址、授權、原始檔名與專案內檔名對照；自行產生的素材也要標明來源性質。
- **ASSET-02**：靜態素材位於 `public/games/<slug>/`，本機路徑與 `/WebGames` 靜態部署前綴皆可載入。
- **EFFECT-01**：音效、粒子、震動與裝飾效果服務玩法回饋，不遮蔽棋盤或阻礙操作。

### 自動與整合檢查

- **TEST-01**：核心純邏輯有最低必要的回歸測試，且該遊戲測試通過。
- **LINT-01**：遊戲、相關 registry 變更與驗證工具通過 ESLint。
- **BUILD-01**：完整 `bun run build` 成功，包含正式靜態匯出。
- **META-01**：registry 品質摘要與最新完成的驗證紀錄一致。若尚未有自動工具，必須人工比對並記錄證據。

整個 repo 的既有、無關 lint 問題不算成單一遊戲的驗證失敗，但必須在紀錄中揭露；完整建置仍是整站整合門檻。真實手機測試可作補充證據，但不是 v1 強制項目。

## 驗證紀錄

- 紀錄存放於 `docs/Games/verification/<slug>/<YYYY-MM-DD>-v<版本>.md`，每次驗證新增一份，不覆寫舊紀錄。
- 驗證者必須是實際執行對應檢查的人；同一份紀錄可列出多位驗證者與各自負責的證據。
- 紀錄必須包含遊戲、基準版本、受驗證的 Git revision、驗證日期、自動檢查、桌面人工試玩、`390 × 844` 行動版人工試玩，以及驗證者。
- 最新「已完成」紀錄支配目前結果；同版本重新驗證失敗時，舊的通過結果不再有效。
- 草稿或資料不完整的檢查不更新 registry 摘要。
- 可能影響玩法、輸入、版面、素材、無障礙或建置結果的後續變更，會使原紀錄成為待重新驗證；純文字文件或無關檔案變更不影響。

驗證紀錄是權威證據，registry 只保存供程式判讀的摘要。每個遊戲都必須明確提供以下欄位；`null` 表示尚未驗證：

```ts
qualityVerification: null | {
  result: "passed" | "failed";
  baselineVersion: number;
  revision: string;
  verifiedAt: string;
  record: string;
};
```

「目前達標」與「待重新驗證」應由摘要事實、目前基準版本及後續相關變更推導，不另存一份手動狀態。導入時所有既有遊戲先設為 `null`；Puzzle Bobble 在完成 v1 紀錄前維持 `beta`。

驗證格式與命名規則見[品質驗證紀錄說明](./verification/README.md)。
